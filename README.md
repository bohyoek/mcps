## 2. 핵심 원칙: "지금"이 아니라 "2029년"을 본다

이 기획은 **3년 뒤에 문을 여는 가게**입니다. 그래서 **지금 잘나가는 것은 근거가 되지 않습니다.**

| ❌ 근거로 쓰지 않는 것 | ✅ 근거로 쓰는 것 |
|---|---|
| "지금 핫한 동네라서" (예: 성수동처럼 현재 뜬 상권) | 2029년 전후로 **확정된** 변화: 신규 역·노선 개통, 아파트 입주, 오피스 준공, 재개발 일정 |
| "요즘 SNS에서 유행하는 빵이라서" | 여러 해에 걸친 **추세**: 인구·가구 구성 변화, 연령 구조, 소비 패턴 통계 |
| 올해 임대료·재료비를 그대로 손익에 넣기 | 올해 값에 **과거 상승률을 적용해 2029년 값으로 환산**한 숫자 |
| 지금 매장 수만 보고 "경쟁이 적다/많다" | 개업·폐업 **추세**로 본 2029년 경쟁 전망 |

- 현재 데이터는 **출발점(기준값)과 추세 계산용**으로만 씁니다.
- 모든 결론에 **"2029년에 왜 그런가"** 를 한 줄로 붙입니다.
- 일정이 아직 확정되지 않은 계획(지연 가능성이 큰 개발 등)은 "미확정"으로 표시하고, 그것 하나에 결론을 걸지 않습니다.

  - **매출 추세:** 제과점 추정매출의 연도별 변화
  - **임대료 추세:** 임대시세 변화 → 2029년 예상 임대료
- 결과: 최종 동네 1곳, 선정 이유, 후보 비교표
- **C에게 넘길 값:** 2029년 예상 월 임대료(평당), 하루 예상 방문 손님 수의 근거, 동네 제과점 평균 매출

### 👤 B. 인테리어 컨셉 + 메뉴구성
- **누가 손님인가:** A가 고른 동네의 **2029년 주 고객층**(연령, 가구 형태, 출근길·주말 등 방문 시간)에서 출발
- **인테리어 컨셉**
  - 매장 형태: 테이크아웃 위주 / 소규모 진열 판매 등 (카페형 좌석 중심 X)
  - 면적(평), 동선(진열대·계산대·주방 비율), 분위기·색·재료 키워드
  - 결과물: 무드보드, 간단한 평면 배치 그림, 컨셉 한 줄
  - 이미지는 **직접 만든 것(AI 생성 포함)이나 무료 라이선스 이미지**만 쓰고, 출처를 남긴다
- **메뉴구성**
  - 대표 메뉴 3개 + 전체 메뉴 10~20개, 가격, 하루 생산량
  - 메뉴별 **원가율**(재료비 ÷ 가격). 재료비는 밀가루·버터·계란 등 주요 재료 가격 추세로 2029년 값 추정
  - "왜 이 메뉴인가"는 2029년 고객층 근거로 설명 (지금 유행 X)
- **C에게 넘길 값:** 매장 면적, 인테리어·설비 비용(추정), 메뉴별 가격·원가율, 객단가(손님 1명이 쓰는 돈) 추정

- **2029년 기준** 월 손익표와 투자 회수 기간
  - **초기 투자:** 보증금, 권리금(있다면), 인테리어, 제빵 설비, 초도 재료
  - **매출:** 하루 손님 수 × 객단가 × 영업일
  - **비용:** 재료비(원가율), 임대료, 인건비(2029년 최저임금 추정), 공과금, 카드수수료, 기타
  - **결과:** 월 영업이익, 손익분기 하루 판매량, 투자 회수 개월 수
- **시나리오 3개:** 비관 / 기본 / 낙관 (손님 수와 원가율을 바꿔서)
- A·B의 값이 오기 전에는 **임시값으로 계산 틀을 먼저 완성**하고, 값이 오면 바꿔 넣는다
- 모든 2029년 값에 **어떻게 환산했는지**(기준 연도 값, 적용한 연평균 상승률)를 적는다

### 👤 D. 영상 PD (영상은 D가 전부 만든다)
- **1단계:** 디자인 시스템(색·폰트·차트 스타일), 스토리보드, 영상 틀 제작. 오프닝은 이때 완성하고, 데이터가 없는 장면은 임시 숫자로 자리만 잡아 둔다
- **3단계:** A·B·C의 재료로 모든 차트·장면을 같은 스타일로 만들고, 전체 대본을 한 사람의 말투로 작성 → 내레이션·자막·배경음 → 최종 mp4
- 숫자는 임의로 바꾸지 않고, 애매하면 담당자에게 묻는다

## 4. 진행 순서와 병렬 구조

1→2·3→4 순서로 서로 값을 넘겨받아야 하므로, **먼저 임시값으로 각자 시작하고, 정해진 시점에 값을 교체**합니다.

```
[0단계 · 함께 20분]  역할 배정, API 키 설정, 영상 톤 합의
        │
[1단계 · 병렬]
   A: 후보 동네 3곳 조사 ──────▶ ① 후보 3곳 공유
   B: 빵집 형태·메뉴 후보 조사 (동네 무관한 부분부터)
   C: 손익 계산 틀을 임시값으로 완성
   D: 디자인 시스템, 스토리보드, 오프닝
        │
[① 체크포인트 · 함께 10분]  A가 후보 3곳 공유 → B는 후보 동네 고객층을 보며 컨셉 방향 잡기
        │
   A: 최종 1곳 선정 ──────────▶ ② 최종 동네 + C에게 넘길 값
        │
[② 체크포인트 · 함께 10분]  최종 동네 확정 → B 컨셉·메뉴 확정 → B·A가 손익 입력값을 C에게
        │
   C: 실제 값으로 손익 계산 → ③ 결과
        │
[③ 체크포인트 · 함께 15분]  손익이 안 맞으면 B가 메뉴 가격·면적 조정, 또는 A가 다른 후보 검토 → 결론 합의
        │
[3단계 · D 집중]  전체 대본 → 차트·장면 → 내레이션 → 최종 mp4 (A·B·C는 검수·질문 대응)
        │
[4단계 · 함께]  최종 시청 → 수정 → main에 합치기
```

**병목 줄이기**
- A는 최종 1곳보다 **후보 3곳을 먼저 빨리** 공유합니다. B·C가 그걸 보고 미리 움직일 수 있습니다.
- C는 값을 기다리지 말고 **계산 틀부터** 만듭니다. 값 교체는 몇 분이면 끝나야 합니다.
- A·B·C는 끝난 부분부터 D에게 바로 넘깁니다.

## 5. 데이터 출처

### 서울 열린데이터광장 API 키 설정 (각자 1번)

1. 서울 열린데이터광장에서 발급받은 **일반 인증키**를 준비합니다.
2. **가장 쉬운 방법:** 쓰고 있는 LLM(에이전트)에게 이렇게 말합니다.
   > "내 서울 API 키는 `발급받은키`야. README대로 `.env`에 저장해 줘."

   에이전트가 레포 루트에 `.env`를 만들고 아래 한 줄을 넣습니다 (직접 만들어도 됩니다):
   ```
   SEOUL_OPENAPI_KEY=발급받은키
   ```
3. `.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다. **키를 코드·README·커밋 메시지·단톡방 공개글에 쓰지 마세요** (퍼블릭 레포입니다).
4. 호출 형식: `http://openapi.seoul.go.kr:8088/{키}/json/{서비스명}/{시작}/{끝}/` (한 번에 최대 1,000건)
   - 필터 인자는 무시되는 경우가 많으니, 1,000건씩 받으면서 **행정동 코드**와 **업종 코드 `CS100005`(제과점)** 로 바로 걸러 저장합니다.

## 6. 결과물 약속 (인터페이스)

```

├── findings.md              # 아래 템플릿
├── SOURCES.md               # 출처 URL + 수집 날짜

│   └── UNITS.md             # 단위표 (필수)
├── for-pnl.csv              # ★ C에게 넘기는 손익 입력값 (A·B만)

└── analysis.py (또는 .ipynb) # 분석·계산 코드
```

**`for-video/` CSV 규칙:** UTF-8, 첫 줄은 한글 열 이름, 단위는 열 이름에 표기(예: `월임대료(만원/3.3㎡)`, `유동인구(명·분기누적)`), 차트 하나에 필요한 행만.

**`for-video/UNITS.md` 필수:** 파일마다 **단위, 뜻, 영상 화면 표기 예시, 기준 시점(현재값인지 2029년 환산값인지)** 을 표로 적습니다.

**`for-pnl.csv` 형식 (A·B → C):**

| 항목 | 값 | 단위 | 기준 | 근거 |
|---|---|---|---|---|
| 월임대료 | 18 | 만원/3.3㎡ | 2029 환산 | 2026Q2 값 × 최근 5년 연평균 상승률 3% (SOURCES.md 2번) |
| 매장면적 | 15 | 평 | — | B 평면안 |

- "기준" 열에 현재값인지 2029년 환산값인지 꼭 적습니다. C는 2029년 값만 계산에 씁니다.

## 7. MCP 실습 가이드

| MCP 서버 | 용도 | 주로 쓰는 사람 |
|---|---|---|
| Filesystem (`@modelcontextprotocol/server-filesystem`) | 데이터·차트 파일 읽고 쓰기 | 모두 |
| Fetch (`mcp-server-fetch`) | 서울 열린데이터 API, 웹페이지 가져오기 | A, B, C |
| Playwright (`@playwright/mcp`) | 브라우저로 golmok 화면 조회(임대시세 등), 지도 캡처, HTML 영상 녹화 | 모두 |
| DuckDuckGo 검색 (`duckduckgo-mcp-server`) | 개발 계획·입주 일정·재료 가격 뉴스 검색 | A, B, C |

- **서울 API는 별도 MCP 없이** Fetch MCP나 Python으로 바로 부릅니다 (주소에 키만 넣으면 JSON이 옴).
- GitHub 작업은 MCP 대신 **`git` 명령어**로 합니다.
- 패키지 이름·설정법은 바뀔 수 있으니 **실습 당일 안내나 공식 문서를 우선**하세요.

### 연결 예시

**Claude Code**

```bash
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem .
claude mcp add fetch -- uvx mcp-server-fetch
claude mcp add playwright -- npx -y @playwright/mcp@latest

```

    "playwright": { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] },

## 9. 협업 규칙

- **각자 자기 폴더만 수정**합니다 (A·B·C는 `parts/자기폴더/`, D는 `video/`). 그래서 충돌이 거의 나지 않습니다.
- 공통 파일(README 등)을 바꿀 땐 단톡방에 먼저 말하기
- 3번 표의 브랜치에서 작업하고, 중간 결과도 자주 push → 다 되면 Pull Request로 `main`에 합치기 (`main`에 직접 push 금지)
- 100MB 넘는 파일(원본 영상 등)은 올리지 말고 공유 드라이브 링크를 남기기
- 레포에 push하려면 레포 주인이 Settings → Collaborators에서 GitHub 아이디를 초대해야 합니다

## 10. 보안·윤리 규칙

- API 키는 **각자 `.env`에만** 두고 절대 커밋하지 않습니다. 실수로 올렸다면 바로 조원에게 알리고 키를 재발급합니다.
- 개인정보(실명, 전화번호, 사람 얼굴 사진)는 수집·업로드하지 않습니다.
- 실제 가게의 사진·로고·메뉴판을 그대로 가져다 쓰지 않습니다.
- 사이트에 무리가 가는 대량 자동 수집은 하지 않고, 제공되는 파일 다운로드를 우선합니다.
- 모든 수치에 출처와 날짜를 남기고, 영상 마지막에 출처를 표기합니다.

## 🤖 LLM 작업 지침

이 README를 읽은 LLM은 다음 순서로 도와주세요.

1. **역할 확인:** 사용자가 A(입지) / B(인테리어·메뉴) / C(손익) / D(영상 PD) 중 누구인지 먼저 묻는다. 대상은 **서울의 베이커리(제과점, `CS100005`)** 이며 **베이커리 카페가 아니다** — 카페형 좌석·음료 중심 기획으로 흐르지 않는다.
2. **2029년 기준:** 2번 원칙을 지킨다. "지금 인기 있는 동네·메뉴"를 근거로 쓰지 않는다. 현재 값은 기준값으로만 쓰고, 2029년 값은 **기준 연도 값과 적용한 상승률을 밝혀 환산**한다. 미확정 계획은 "미확정"으로 표시한다.
3. **환경 확인:** 사용하는 LLM 도구와 연결된 MCP 서버를 확인하고, 부족하면 7번 예시로 연결을 돕는다.
4. **자기 범위만:** 사용자의 역할 폴더(`parts/...` 또는 `video/`)에서만 파일을 만들고 수정한다. 다른 역할의 폴더는 읽기만 한다. B·C는 다른 사람의 `for-pnl.csv`와 `findings.md`를 읽어 입력값으로 쓴다. 아직 없으면 임시값으로 진행하고 "임시값"이라고 표시한다.
5. **데이터와 API 키:** 5번의 서울 열린데이터 API를 우선 쓴다. 접근 제한을 우회하지 않는다.
   - 레포 루트 `.env`에 `SEOUL_OPENAPI_KEY`가 없으면 사용자에게 키를 달라고 한다.
   - 사용자가 키를 주면 **레포 루트 `.env`에 `SEOUL_OPENAPI_KEY=키` 한 줄로 저장**한다(이미 있으면 그 줄만 바꾼다). 저장 후 `git check-ignore .env`로 커밋 제외인지 확인하고, 키로 1건만 호출해 작동하는지 확인한다.
   - 코드에서는 키를 항상 `.env`에서 읽는다. 키 값을 코드·다른 파일·커밋 메시지·PR·답변에 다시 쓰지 않는다. 커밋 전에 키 값이 스테이징된 파일에 없는지 확인한다.
6. **약속된 형식:** A·B·C라면 6번의 폴더 구조, `findings.md` 템플릿, `for-video/UNITS.md`, `for-pnl.csv`(A·B) 형식을 그대로 따르고, 차트 디자인·대본·영상은 만들지 않는다(D 몫). D라면 8번 장면표와 폴더 구조를 따르고, 데이터가 없는 장면은 임시 숫자로 자리를 잡아 둔다.
7. **사실만:** 숫자를 지어내지 않는다. 모든 수치는 `SOURCES.md`에 URL과 수집 날짜를 남기고, 추정치는 "추정"이라고 표시한다.
8. **작게, 자주:** 한 단계씩 끝내고 결과를 보여 준 뒤 다음으로 넘어간다. 역할 브랜치에서 커밋하고, push 전에는 사용자에게 확인받는다. `main`에 직접 push하지 않는다.
