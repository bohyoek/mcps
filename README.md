## 1. 프로젝트 목표

**약 3년 뒤(2029년경) 카페를 개업한다고 가정하고, 후보 상권을 분석해 그 결과를 약 2분짜리 영상으로 만든다.**

- 결과물: 2분(±15초) 내외의 16:9 영상 1편 (MP4 권장)
- 과정: 여러 **MCP(Model Context Protocol) 서버**를 LLM에 연결해 데이터 수집 → 분석 → 시각화 → 영상 제작까지 진행
- 핵심 질문: *"지금이 아니라 3년 뒤에도 이 상권에서 카페가 살아남을 수 있을까?"*

## 2. 전체 흐름

```
① 지역·컨셉 정하기 → ② 데이터 수집(MCP) → ③ 분석 → ④ 시각화 → ⑤ 대본·스토리보드 → ⑥ 영상 제작 → ⑦ 발표
```

| 단계 | 하는 일 | 주로 쓰는 MCP / 도구 |
|---|---|---|
| ① 기획 | 후보 지역 2~3곳, 카페 컨셉(테이크아웃/디저트/작업용 등) 결정 | — |
| ② 수집 | 공공데이터·지도·뉴스·부동산 정보 모으기 | Fetch, 브라우저(Playwright), 웹검색, 파일시스템 |
| ③ 분석 | 유동인구, 경쟁점, 임대료, 개폐업률, 개발 계획 정리 | 파일시스템, Python 실행 |
| ④ 시각화 | 지도, 차트, 비교표 이미지 만들기 | Python(matplotlib/plotly), HTML |
| ⑤ 대본 | 2분 내레이션 대본 + 장면 구성 | LLM |
| ⑥ 영상 | 모션그래픽 HTML → 녹화, 또는 이미지+TTS 편집 | 브라우저(Playwright), ffmpeg |
| ⑦ 공유 | GitHub에 결과 올리기 | GitHub MCP |

## 4. 참고할 데이터 출처

> 대부분 무료 회원가입 + API 키 발급이 필요합니다. **API 키는 절대 커밋하지 마세요** ([6. 보안](#6-보안-규칙) 참고).

- **공공데이터포털** (data.go.kr) — 소상공인시장진흥공단 상가(상권)정보, 국토교통부 상업업무용 부동산 실거래가
- **소상공인시장진흥공단 상권정보** (sg.sbiz.or.kr) — 상권 분석 리포트
- **서울 열린데이터광장 / 서울시 상권분석서비스** — 서울이라면 추정매출, 유동인구, 점포 수 등 (서울 외 지역은 해당 시·도 데이터 확인)
- **통계청 SGIS 통계지리정보서비스** — 지역별 인구·가구·사업체
- **한국부동산원 R-ONE** — 상가 임대료·공실률 동향
- **카카오맵 / 네이버 지도 API** — 주변 카페 검색, 위치 좌표
- **지자체 도시계획·뉴스** — 재개발, 신규 역, 대형 개발 계획

## 5. MCP 실습 가이드

MCP는 LLM에게 "도구"를 꽂아 주는 표준입니다. 실습에서 아래 서버들을 하나씩 연결해 봅니다.
(패키지 이름과 설정법은 바뀔 수 있으니 **실습 당일 안내나 공식 문서를 우선**하세요.)

| MCP 서버 | 용도 | 비고 |
|---|---|---|
| Filesystem (`@modelcontextprotocol/server-filesystem`) | 수집한 데이터·이미지 파일 읽고 쓰기 | 프로젝트 폴더만 허용 |
| Fetch (`mcp-server-fetch`) | 웹페이지·API 응답 가져오기 | Python `uvx` 필요 |
| Playwright (`@playwright/mcp`) | 브라우저 조작, 지도 화면 캡처, HTML 영상 녹화 | Node.js 필요 |
| 웹검색 (Brave Search 등) | 개발 계획·뉴스 검색 | API 키 필요 |
| GitHub | 이슈·PR·결과물 관리 | 토큰 또는 OAuth |
| 지도 / 공공데이터 MCP | 카카오맵·공공데이터 조회 | 실습에서 소개되는 서버 사용 |

### 연결 예시

**Claude Code**

```bash
claude mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem .
claude mcp add playwright -- npx -y @playwright/mcp@latest
claude mcp add fetch -- uvx mcp-server-fetch
```

**Claude Desktop / Cursor 등 (JSON 설정)**

```json
{
  "mcpServers": {
    "filesystem": { "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "<이 레포의 절대경로>"] },
    "playwright": { "command": "npx", "args": ["-y", "@playwright/mcp@latest"] },
    "fetch":      { "command": "uvx", "args": ["mcp-server-fetch"] }
  }
}
```

사전 설치: **Node.js 18+**, **Python 3.10+ / uv**, (영상 변환용) **ffmpeg**

## 6. 보안 규칙

- API 키·토큰은 `.env` 파일에만 저장하고, `.env`는 커밋하지 않습니다 (`.gitignore`에 포함).
- 개인정보(실명, 전화번호, 개인 사진)가 담긴 데이터는 올리지 않습니다.
- 수집한 데이터의 **출처와 날짜**를 꼭 기록합니다 (영상 마지막에 출처 표기).

## 7. 폴더 구조

```
.
├── README.md            # 이 문서 (프로젝트 기준)
├── data/
│   ├── raw/             # 수집한 원본 데이터 (출처·날짜를 파일명이나 SOURCES.md에)
│   └── processed/       # 정리한 데이터
├── analysis/            # 분석 코드·노트북, 결과 요약 (findings.md)
├── assets/              # 차트·지도 이미지, 아이콘, 폰트
├── video/
│   ├── script.md        # 2분 내레이션 대본
│   ├── storyboard.md    # 장면별 구성
│   └── ...              # 모션그래픽 HTML, 최종 mp4
└── docs/                # 회의록, 역할 분담
```

폴더는 필요할 때 만들면 됩니다.

## 8. 2분 영상 구성 (예시)

| 시간 | 장면 | 내용 |
|---|---|---|
| 0:00–0:10 | 오프닝 | "3년 뒤, 이곳에 카페를 연다면?" + 카페 컨셉 |
| 0:10–0:25 | 후보 지역 소개 | 지도 위 위치, 주변 랜드마크 |
| 0:25–0:50 | 수요 | 유동인구·연령대·시간대 차트 |
| 0:50–1:10 | 경쟁 | 주변 카페 지도, 개·폐업 추세 |
| 1:10–1:30 | 비용 | 임대료·권리금, 예상 손익 간단 계산 |
| 1:30–1:45 | 3년 뒤 변화 | 개발 계획, 인구 변화, 리스크 |
| 1:45–2:00 | 결론 | 추천 여부 한 줄 + 데이터 출처 |

**영상 만드는 방법 (택 1)**

1. **HTML 모션그래픽 → 녹화:** HTML/CSS/JS로 장면을 만들고 Playwright로 녹화한 뒤 ffmpeg로 mp4 변환
2. **이미지 + 내레이션 편집:** 차트·지도 이미지를 만들고 TTS 음성과 함께 영상 편집 도구(CapCut, Premiere 등)나 ffmpeg로 합치기

## 9. 협업 방법

- 작업 전 `git pull`, 작업은 브랜치에서 (`이름/작업내용`, 예: `minji/data-population`)
- 끝나면 Pull Request로 합치기 — `main`에 직접 push하지 않기
- 큰 파일(원본 영상, 대용량 CSV)은 올리지 말고 공유 드라이브 링크를 `docs/`에 적기
- 역할 예시: **데이터 수집** / **분석·시각화** / **대본·스토리보드** / **영상 제작** / **발표**

## 🤖 LLM 작업 지침

이 README를 읽은 LLM은 다음 순서로 도와주세요.

1. **먼저 묻기:** 사용자의 역할(위 9번), 분석할 후보 지역, 카페 컨셉이 정해졌는지 확인한다. 정해지지 않았으면 함께 정한다.
2. **환경 확인:** 사용자가 어떤 LLM 도구를 쓰는지, 어떤 MCP 서버가 연결돼 있는지 확인하고, 필요한 MCP 연결을 5번 예시를 참고해 안내한다.
3. **목표 유지:** 모든 작업은 "3년 뒤 카페 창업 상권분석 2분 영상"이라는 최종 목표에 맞춘다. 3번 표의 "3년 뒤" 관점을 빠뜨리지 않는다.
4. **출처 기록:** 데이터를 수집하면 출처 URL과 수집 날짜를 `data/raw/SOURCES.md`에 남긴다. 숫자를 지어내지 않고, 추정치는 추정이라고 표시한다.
5. **보안:** API 키·토큰을 코드나 커밋에 넣지 않고 `.env`를 쓰게 한다.
6. **폴더 구조:** 7번 구조에 맞춰 파일을 만든다.
7. **협업:** `main`에 직접 커밋·push하지 말고 브랜치와 PR을 쓰도록 안내한다. push 전에는 사용자에게 확인을 받는다.
8. **작게 나누기:** 한 번에 하나의 단계(수집 → 분석 → 시각화 → 영상)를 끝내고 결과를 보여 준 뒤 다음으로 넘어간다.
